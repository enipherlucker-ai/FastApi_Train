# Домен, сайт на Nuxt на сервере и SSH-туннель к базе — для чайников 😄

**Цель урока:** после него у проекта есть свой адрес вида `https://example.ru`, на нём открывается твоя страница входа на Nuxt, а с компьютера ты смотришь боевую базу в PyCharm или DBeaver, не открывая её в интернет. И главное: ты понимаешь, что происходит на каждом шаге, а не просто повторяешь команды.

Три части урока:

1. **Домен.** Что это вообще такое, где купить из России (картой МИР или по СБП), что поменялось с 1 сентября 2026 года для `.ru`, как привязать домен к серверу и проверить, что всё дошло.
2. **Форма входа.** Доводим страницу входа до состояния «не стыдно выложить в интернет» и выкатываем её на сервер вместе с текущим CI/CD.
3. **SSH-туннель к PostgreSQL.** Как смотреть боевую базу из PyCharm или DBeaver под своей учёткой и своей ролью «только чтение».

Урок опирается на текущий `main`: вход на FastAPI и Nuxt из [урока по Nuxt](nuxt-auth-for-beginners.md) и CI/CD с выкаткой на сервер из [урока по деплою](deploy-cicd-for-beginners.md). Особенно на **раздел 10 урока по деплою** («Сайт: Nuxt в Docker, домен и HTTPS»): там уже разобраны `frontend/Dockerfile`, Caddy, белый список путей API и `APP_ENV=prod`. Здесь это **не повторяется**, а связывается в один порядок действий и дополняется тем, чего там не было.

**Готового кода в репозитории нет.** Всё, что описано ниже, пишешь ты сам. Проверено 23.10.2026 на Nuxt 4.6, Node.js 22, Caddy 2, PostgreSQL 18 и Ubuntu на сервере.

## 0. Как проходить урок

Правила прежние:

1. **Печатай руками.** Не копируй блоки кода в файлы.
2. **Одна возможность — одна проверка.** Купил домен — проверил DNS. Поправил форму — проверил дома. Выкатил — проверил на сервере. Не делай три вещи подряд без проверки.
3. **Сначала предскажи — потом запусти.** Перед каждой командой скажи себе, что она должна вывести.
4. **Ответы — в свёрнутых блоках.** Открывай их только после своей попытки.

И одно новое правило:

5. **Деньги и паспорт — только осознанно.** В этом уроке впервые есть шаг, который стоит денег каждый год и привязан к твоему паспорту (домен). Прочитай раздел 3 целиком **до** того, как нажать «Оплатить».

План: что строим (1) → шаг ноль в песочнице (2) → домен (3) → доводим форму входа (4) → выкатываем сайт (5) → SSH-туннель к базе (6) → ловушки (7) → диагностика (8) → тренировка (9) → повторение по памяти (10) → шпаргалка (11) → источники (12).

Нормально проходить урок за три вечера: вечер на домен (разделы 2–3, потом ждёшь DNS), вечер на форму и выкатку (4–5), вечер на туннель (6).

## 1. Что мы строим и словарь

Сейчас на сервере работают `api`, `pg_database` и `bot`. К концу урока картина такая:

```text
                         интернет
                            │
    браузер ──https://example.ru──► caddy :443 ──► web :3000 (Nuxt) ──/api/auth/*──► api :8000 ──► pg_database :5432
                                                                                       ▲                   ▲
                                                                     bot ──────────────┘                   │
                                                                                                           │
    твой компьютер ══SSH-туннель (порт 22)══► сервер ──► 127.0.0.1:5432 ───────────────────────────────────┘
    PyCharm / DBeaver → 127.0.0.1:15432
```

Наружу открыты только 22 (SSH), 80 и 443 (Caddy). База и API в интернет **не открыты**: к базе ты ходишь через SSH, а API видно только через три пути, которые пропускает Nuxt.

Словарь:

| Слово | Что значит |
|---|---|
| **Домен** | Имя вроде `example.ru`, которое ты арендуешь на год. Не покупаешь навсегда, а арендуешь и продлеваешь. |
| **Регистратор** | Компания, у которой ты арендуешь домен (REG.RU, Timeweb, Beget, RU-CENTER и т. д.). |
| **Реестр** | Организация, которая ведёт зону целиком. Для `.ru` и `.рф` это Координационный центр доменов. Регистраторы продают домены от его имени. |
| **DNS** | «Телефонная книга» интернета: по имени `example.ru` находит IP-адрес сервера. |
| **DNS-запись** | Строка в этой книге. `A` — имя → IPv4-адрес. `AAAA` — имя → IPv6-адрес. `CNAME` — имя → другое имя. |
| **NS-серверы** | Серверы, которые хранят записи твоего домена. Обычно это DNS-серверы регистратора. |
| **TTL** | Сколько секунд чужие DNS-серверы могут помнить запись, прежде чем спросить снова. |
| **`@`** | В панели DNS означает «сам домен без приставки», то есть `example.ru`. |
| **Сертификат** | Документ, которым сервер доказывает браузеру «я правда `example.ru`». Без него нет `https://`. Caddy получает его сам у Let's Encrypt. |
| **SSH-туннель** | Труба через SSH-соединение: программа на твоём компьютере стучится в свой локальный порт, а попадает в порт на сервере. |

### Как работает DNS на пальцах

Когда ты вводишь `example.ru` в браузере:

1. Компьютер спрашивает свой DNS-сервер (обычно провайдера или `1.1.1.1`): «какой IP у `example.ru`?».
2. Тот не знает и спрашивает по цепочке: корневые серверы → серверы зоны `.ru` → **NS-серверы твоего домена** (например, `ns1.reg.ru`).
3. NS-сервер отвечает: «`A`-запись `example.ru` = `203.0.113.10`, TTL 300».
4. Ответ запоминается на 300 секунд, браузер идёт на `203.0.113.10:443`.

<details><summary>Вопрос 1. Ты поменял A-запись, а у тебя всё ещё открывается старый IP. Почему, и что с этим делать?</summary>

Где-то по пути (твой роутер, DNS провайдера, сам Windows) лежит старый ответ, и он «живёт» до конца своего TTL. Поэтому:

- до переезда сервера ставь маленький TTL (300 секунд), а не сутки;
- проверяй через конкретный публичный DNS-сервер: `Resolve-DnsName example.ru -Server 1.1.1.1` или `nslookup example.ru 1.1.1.1`;
- кеш самого Windows сбрасывается командой `ipconfig /flushdns`.
</details>

<details><summary>Вопрос 2. Зачем домен вообще, если сайт можно открыть по IP?</summary>

Три причины, и третья главная:

1. Человеку проще запомнить имя, чем `203.0.113.10`.
2. Если сменишь сервер, поменяешь одну A-запись, а адрес для людей останется прежним.
3. **Let's Encrypt не выдаёт обычные сертификаты на голый IP**, а без сертификата нет `https://`. А без `https://` при `APP_ENV=prod` вход вообще не работает: cookie с флагом `Secure` браузер по `http://` не сохранит (вопрос 16 урока по деплою).
</details>

## 2. Шаг ноль: песочница

Прежде чем тратить деньги, потрогай всё бесплатно.

### 2.1. DNS чужих сайтов

В PowerShell:

```powershell
Resolve-DnsName github.com -Server 1.1.1.1
Resolve-DnsName www.github.com -Server 1.1.1.1
Resolve-DnsName github.com -Type NS -Server 1.1.1.1
Resolve-DnsName ya.ru -Type AAAA -Server 1.1.1.1
```

Предскажи до запуска: где будет `A`, где `CNAME`, где `AAAA`.

<details><summary>Что ты должен увидеть</summary>

- `github.com` — одна или несколько записей `A` с IP-адресами.
- `www.github.com` — запись `CNAME` на `github.com`, а уже за ней `A`.
- `-Type NS` — имена NS-серверов, которые хранят записи этого домена.
- `ya.ru -Type AAAA` — IPv6-адрес, длинный, с двоеточиями.

Если `Resolve-DnsName` не работает (старая PowerShell), то же умеет `nslookup -type=NS github.com 1.1.1.1`.
</details>

### 2.2. Туннель к тому, что уже есть: `/docs` боевого API

На сервере API слушает `127.0.0.1:8000`, то есть снаружи его не видно. Проверь это и сразу попробуй первый туннель. В PowerShell:

```powershell
Test-NetConnection <IP-сервера> -Port 8000
ssh -N -L 18000:127.0.0.1:8000 jenifer@<IP-сервера>
```

Первая команда должна сказать `TcpTestSucceeded : False`: снаружи порт закрыт. Вторая «зависнет» без вывода — так и должно быть, туннель открыт, пока окно открыто. Открой в браузере `http://127.0.0.1:18000/docs`: это Swagger **боевого** API. Закрой туннель через `Ctrl+C` и обнови страницу: она перестанет открываться.

<details><summary>Вопрос 3. Разбери команду по кусочкам: что значит каждая часть?</summary>

- `ssh ... jenifer@<IP>` — обычный вход на сервер под твоим пользователем.
- `-N` — «не запускай на сервере никакую команду, мне нужен только туннель». Без `-N` откроется ещё и командная строка сервера.
- `-L 18000:127.0.0.1:8000` — **L**ocal forwarding: «слушай на **моём** компьютере порт `18000`; всё, что туда придёт, передай по SSH на сервер, а сервер пусть отправит это на `127.0.0.1:8000`».

Ключевой момент: `127.0.0.1:8000` в этой команде — это адрес **с точки зрения сервера**. Для сервера `127.0.0.1` — он сам, а на нём API.
</details>

**Не вызывай в этом Swagger ничего, кроме `GET`.** Это настоящая база.

### 2.3. Сборка Nuxt «как на сервере» у себя

Дома ты запускаешь `npm run dev`: режим разработки, горячая перезагрузка, подробные ошибки. На сервере работает собранный сайт. Посмотри на него у себя. В папке `frontend`:

```powershell
npm run build
node .output/server/index.mjs
```

Открой `http://localhost:3000/login`. Это тот же код, что будет в контейнере `web`. Если `api` дома запущен в Docker, вход тоже работает (прокси пока старый, `'/api/**'`). Останови через `Ctrl+C`.

<details><summary>Вопрос 4. Чем собранный сайт отличается от npm run dev?</summary>

- Нет горячей перезагрузки: поменял файл — пересобирай.
- Код сжат и разбит на файлы в `.output/public/_nuxt`, это видно во вкладке **Network** (F12).
- Ошибки на странице короткие, без стека: в продакшене подробности не показывают посторонним.
- Настройки вроде `routeRules` **запечены** при сборке (вопрос 14 урока по деплою).

Поэтому «дома в dev работает» ещё не значит «работает собранный». Перед выкаткой всегда собирай.
</details>

## 3. Домен

### 3.1. Какую зону выбрать

| Зона | Плюсы | Минусы |
|---|---|---|
| **`.ru`** | Дёшево, все российские регистраторы, оплата МИР и СБП | С 1 сентября 2026 владелец подтверждает личность через Госуслуги (ниже) |
| **`.рф`** | По-русски | В коде, логах и сертификатах превращается в `xn--...` (punycode), неудобно для разработчика |
| **`.com`, `.dev`, `.io` и другие международные** | Закон о Госуслугах их не касается | У российских регистраторов дороже; у зарубежных (Namecheap, Porkbun, Cloudflare) российская карта не пройдёт |
| **`.su`** | Экзотика | Те же правила, что у `.ru`, а репутация зоны хуже |

**Рекомендация для учебного проекта: `.ru`** у российского регистратора. Сервер за границей и домен `.ru` прекрасно работают вместе: домену всё равно, где стоит сервер.

### 3.2. Что поменялось с 1 сентября 2026 года

С 1 сентября 2026 года действует закон № 569-ФЗ: администратор домена в зонах `.ru`, `.рф` и `.su` проходит **идентификацию через Госуслуги (ЕСИА)** в личном кабинете регистратора. Без неё новый домен не зарегистрируют, а продление и смена данных, по заявлениям регистраторов, тоже будут требовать подтверждения. Для тех, кто не прошёл проверку, есть переходный период до 18 января 2027 года.

Что это значит для тебя:

- Нужна **подтверждённая** учётная запись на Госуслугах.
- Домен будет записан **на тебя лично**, по паспорту. Это нормально для `.ru`: так было и раньше, просто теперь проверка строже.
- Для физических лиц в публичном WHOIS вместо имени показывается `Private Person`: твои ФИО и телефон посторонние не увидят. Проверь это у своего регистратора после регистрации: `whois example.ru` или поиск WHOIS на сайте Координационного центра.

> ⚠️ Правила продления ещё уточняются. Перед покупкой открой на сайте выбранного регистратора страницу про идентификацию через Госуслуги и прочитай, что они требуют **сегодня**.

### 3.3. Где купить: главное — цена продления

Первый год почти везде стоит копейки, а дальше цена у разных регистраторов отличается в разы. Ориентиры из сравнения в мае 2026 года (цены меняются, сверяй в корзине):

| Регистратор | Первый год | Продление |
|---|---|---|
| Beget, Timeweb | ~200 ₽ | ~400 ₽ |
| SpaceWeb, Sprinthost | ~180–190 ₽ | ~320–340 ₽ |
| REG.RU | ~170 ₽ | ~1200 ₽ |
| RU-CENTER (nic.ru) | ~750 ₽ | дороже 3000 ₽ для физлиц |

Если твой VPS-провайдер тоже продаёт домены (у многих российских хостеров так), удобно держать всё в одном кабинете. Но выбирай по цене **продления**, а не первого года.

Чек-лист перед оплатой:

- [ ] Цена продления на второй год написана явно.
- [ ] В кабинете есть **двухфакторная аутентификация** (код из приложения или по SMS). Кабинет регистратора — это ключ от твоего домена: кто в него вошёл, тот перенаправит сайт куда угодно.
- [ ] Включено **автопродление** и привязана карта, или стоит напоминание в календаре за месяц. Просроченный домен через некоторое время освобождается, и его может купить кто угодно.
- [ ] Оплата МИР или СБП принимается (у российских регистраторов почти всегда да).
- [ ] Ты прочитал их страницу про Госуслуги.

### 3.4. Как выбрать имя

- Латиница, коротко, без цифр, которые можно спутать с буквами (`0` и `o`, `1` и `l`).
- Дефис допустим, но его трудно продиктовать голосом.
- Проверка, свободно ли имя: поиск на сайте регистратора или `whois`.
- Имя потом можно поменять (купить другое), но всё, что на него завязано (закладки, Telegram-ссылки, SSH-конфиг), придётся переделывать.

<details><summary>Вопрос 5. Почему не взять бесплатный поддомен вроде myproject.какой-то-сервис.net?</summary>

Для экспериментов можно, но:

- поддоменом управляешь не ты: сервис может закрыться или забрать имя;
- у Let's Encrypt есть лимиты сертификатов **на домен верхнего уровня**: на популярных бесплатных доменах их иногда исчерпывают другие пользователи;
- часть таких сервисов доступна из России нестабильно.

200–400 ₽ в год за своё имя — это недорого за предсказуемость.
</details>

### 3.5. Покупка

1. Регистрация в кабинете регистратора, включение двухфакторной аутентификации.
2. Идентификация через Госуслуги (кнопка в кабинете, займёт 10–15 минут при подтверждённой учётке).
3. Поиск имени, оплата.
4. Подожди, пока домен **делегируют**, то есть пока зона `.ru` начнёт отвечать «записи этого домена хранятся на таких-то NS-серверах». Обычно это от нескольких минут до нескольких часов.

Проверка делегирования:

```powershell
Resolve-DnsName example.ru -Type NS -Server 1.1.1.1
```

Когда в ответе появились NS-серверы регистратора (например, `ns1.reg.ru`), можно настраивать записи.

### 3.6. DNS-записи для сервера

В кабинете регистратора найди «Управление DNS» или «DNS-записи» и создай:

| Тип | Имя | Значение | TTL |
|---|---|---|---|
| `A` | `@` | IP твоего сервера | 300 |
| `A` | `www` | IP твоего сервера | 300 |

Регистратор при создании домена мог сам добавить записи «по умолчанию» (на свою страницу-заглушку или парковку). **Удали их**, иначе домен будет попеременно указывать то на заглушку, то на твой сервер.

<details><summary>Вопрос 6. Нужна ли запись AAAA (IPv6)?</summary>

Только если у сервера есть IPv6 **и** ты проверил, что сайт по нему отвечает. Если запись `AAAA` есть, а по IPv6 сервер не отвечает (провайдер выдал адрес, но не настроил, или файрвол закрыт), то:

- часть посетителей с IPv6 не откроет сайт;
- Let's Encrypt **предпочитает IPv6** при проверке домена, и Caddy не получит сертификат.

Для учебного проекта проще: **без `AAAA`**. Если у регистратора она создалась сама — удали.
</details>

<details><summary>Вопрос 7. Почему у www тоже A, а не CNAME на @?</summary>

Можно и `CNAME www → example.ru.`, это тоже правильно: тогда при смене IP меняешь одну запись вместо двух. Два `A` проще понять новичку и чуть быстрее (на один шаг поиска меньше). Выбирай любой вариант, но не оба сразу: `CNAME` нельзя ставить на имя, у которого есть другие записи.
</details>

Проверка (через 5–30 минут):

```powershell
Resolve-DnsName example.ru -Type A -Server 1.1.1.1
Resolve-DnsName www.example.ru -Type A -Server 1.1.1.1
Resolve-DnsName example.ru -Type A -Server 8.8.8.8
```

Все три должны вернуть IP сервера. Проверяй **двумя** разными публичными DNS: если один уже знает новую запись, а другой нет, значит ещё не везде обновилось, подожди.

### 3.7. Домен в SSH

Теперь можно ходить на сервер по имени: `ssh jenifer@example.ru`. Удобнее завести короткое имя в файле `C:\Users\Jenifer\.ssh\config` (создай, если его нет, без расширения `.txt`):

```text
Host fastapi
    HostName example.ru
    User jenifer
    IdentityFile ~/.ssh/id_ed25519
    ServerAliveInterval 30
    ServerAliveCountMax 3
```

После этого: `ssh fastapi`. `ServerAliveInterval 30` раз в 30 секунд шлёт «я жив», чтобы роутер не обрывал тихое соединение. Для туннелей это особенно важно: туннель к базе часто стоит без трафика минутами.

> ⚠️ При первом входе по имени ssh снова спросит `Are you sure you want to continue connecting`: для него `example.ru` — новое имя, хотя сервер тот же. Отпечаток должен **совпасть** с тем, что ты видел при входе по IP. Сравни: `ssh-keygen -F <IP>` и `ssh-keygen -F example.ru` после входа.

## 4. Доводим форму входа

Дома форма работает. Но в интернете к ней придут не только ты, но и боты, которые перебирают пароли и шлют мусор. Пройдись по коду с этим взглядом. Каждый пункт — отдельная правка и отдельная проверка **дома** (`compose.yaml` + `npm run dev`).

### 4.1. Ограничь размер логина и пароля при входе

Открой `app/schemas/auth.py`. У `RegisterIn` есть ограничения `min_length`, `max_length`, а у `LoginIn` — просто `str`.

<details><summary>Вопрос 8. Чем опасен пароль без ограничения длины именно при входе?</summary>

Argon2 специально медленный: на проверку одного пароля уходят десятки миллисекунд и десятки мегабайт памяти. Время растёт и с длиной пароля. Если бот пришлёт пароль на 10 МБ, сервер честно начнёт его хешировать (даже для несуществующего пользователя: там проверяется `DUMMY_HASH`). Сотня таких запросов — и твои 2 vCPU заняты только этим, а сайт и бот стоят. Это называется отказ в обслуживании (DoS).

Ограничение длины проверяет Pydantic **до** того, как дело дойдёт до argon2, и FastAPI сразу отвечает `422`.
</details>

Задание: задай `LoginIn.login` и `LoginIn.password` ограничение `max_length` (такое же, как у регистрации). `min_length` для входа не обязателен: короткий пароль просто не совпадёт.

Проверка дома в Swagger (`http://127.0.0.1:8000/docs`): `POST /auth/login` с паролем из 200 символов → `422`, с правильным паролем → `200`.

### 4.2. Пользователь с логином, но без пароля

Посмотри на `login()` в `app/api/auth.py`. Предскажи: что будет, если у пользователя в базе есть `login`, а `password_hash` равен `NULL`? (Колонки в `02_table_users.sql` допускают `NULL`.)

<details><summary>Ответ</summary>

`stored_hash` станет `None`, и `verify_password(data.password, None)` упадёт внутри `pwdlib`. FastAPI ответит `500 Internal Server Error`, а на странице появится «Сервер не отвечает». Причём только для этого логина: по ответу 500 вместо 401 посторонний понимает, что такой логин **существует**.

Правильно: если хеша нет, вести себя так же, как если пользователя нет. Проверить `DUMMY_HASH` (чтобы время ответа было одинаковым) и вернуть `401`.
</details>

Задание: поправь выбор `stored_hash` и условие отказа так, чтобы пользователь без `password_hash` получал `401`, а время ответа не отличалось.

Проверка дома: через `docker compose exec pg_database psql ...` поставь какому-нибудь пользователю `login = 'nohash'` при `password_hash = NULL`, войди как `nohash` → `401`, в логах `api` нет трейсбека.

<details><summary>Подсказка, если застрял</summary>

Достаточно, чтобы в `stored_hash` попадал `DUMMY_HASH`, когда `user is None` **или** `user.password_hash` пустой. А в условии отказа — та же проверка вместо одного `user is None`.
</details>

### 4.3. Честные сообщения об ошибках на странице

Сейчас в `login.vue` любой код, кроме `401`, превращается в «Сервер не отвечает». Узнай, какие коды реально бывают. Проверено на собранном Nuxt с белым списком из урока по деплою:

| Ситуация | Что приходит в `$fetch` | Что показать |
|---|---|---|
| Неверный логин или пароль | `statusCode: 401` | «Неверный логин или пароль» |
| Слишком длинный ввод (4.1) | `statusCode: 422` | «Слишком длинный логин или пароль» |
| `api` упал, Nuxt жив | `statusCode: 502` (Bad Gateway от прокси Nuxt) | «Сервер не отвечает, попробуй позже» |
| Ошибка в коде API | `statusCode: 500` | «Что-то сломалось на сервере» |
| Нет интернета у самого пользователя | `statusCode` нет (`undefined`) | «Нет связи. Проверь интернет» |

Задание: перепиши `catch` в `onSubmit` так, чтобы каждая строка таблицы давала своё сообщение. Удобно через `if`/`else if` или через объект «код → текст» с запасным текстом для всего остального.

<details><summary>Вопрос 9. Зачем различать 502 и «нет интернета», если человеку всё равно не войти?</summary>

Потому что действия разные. «Нет связи» — проблема у человека, пусть проверит Wi-Fi. «Сервер не отвечает» — проблема у тебя, человек тут ни при чём. А когда что-то сломается у тебя самого, правильное сообщение экономит полчаса диагностики: ты сразу знаешь, смотреть логи `api` или свой роутер.
</details>

Ещё две мелочи в той же функции:

- Убирай пробелы по краям логина перед отправкой: `login.value.trim()`. Телефон любит добавлять пробел после автоподстановки. Пароль **не** трогай: пробел в пароле может быть настоящим.
- Сообщение об ошибке должно исчезать, когда человек снова начинает печатать. Подсказка: `watch` на `login` и `password`, который очищает `errorText`. Или просто очищай в начале `onSubmit`, как сейчас, это тоже допустимо.

### 4.4. Кнопка «Выйти», когда сервер не ответил

Посмотри на `onLogout` в `index.vue`. Если `$fetch` упадёт (например, `api` перезапускается во время деплоя), функция оборвётся на первой строке, ничего не покажет, а человек будет жать кнопку снова и снова.

Задание: оберни в `try`/`catch`, при ошибке покажи текст «Не получилось выйти, попробуй ещё раз». Не очищай `currentUser`, если сервер не подтвердил выход.

<details><summary>Вопрос 10. Почему не очистить currentUser и не перейти на /login в любом случае?</summary>

Потому что cookie сессии осталась. На `/login` сработает глобальный middleware: `currentUser` пустой → `loadCurrentUser()` → `/api/auth/me` (сервер уже поднялся) → пользователь найден → редирект обратно на `/`. Человек нажал «Выйти» и… оказался на главной. Это путает больше, чем честное «не получилось».

Это общее правило: **интерфейс не должен показывать результат, которого сервер не подтвердил.**
</details>

### 4.5. Язык и заголовок страницы

Открой собранную страницу и посмотри исходный код (`Ctrl+U`): тег `<html>` без `lang`, а `<title>` нет вообще. Во вкладке браузера видно `localhost:3000/login`.

Задание: в `nuxt.config.ts` добавь раздел `app.head` с `htmlAttrs: { lang: 'ru' }` и `title`. На странице входа можно переопределить заголовок через `useHead({ title: 'Вход' })` в `<script setup>`.

<details><summary>Вопрос 11. Зачем lang="ru", если всё и так по-русски?</summary>

- Браузер правильно переносит слова и предлагает (или не предлагает) перевод страницы.
- Экранные дикторы для незрячих читают текст с русским произношением, а не с английским.
- Проверка орфографии в полях ввода работает на нужном языке.

Проверено: после сборки в HTML появляется `<html lang="ru">` и `<title>`.
</details>

### 4.6. Страница ошибки

Сейчас незалогиненный человек на любом несуществующем адресе попадает на `/login` (так работает middleware), а залогиненный видит стандартную страницу ошибки Nuxt на английском.

### 5.2. Caddyfile: `www` и тестовые сертификаты

В уроке по деплою Caddyfile обслуживает один адрес. Добавь `www`, чтобы `www.example.ru` перенаправлял на `example.ru`, и строку для тестового центра сертификации:

```text
{
	# acme_ca https://acme-staging-v02.api.letsencrypt.org/directory
}

{$SITE_DOMAIN} {
	encode zstd gzip
	reverse_proxy web:3000
}

www.{$SITE_DOMAIN} {
	redir https://{$SITE_DOMAIN}{uri} permanent
}
```

- Блок `{ ... }` в начале — глобальные настройки Caddy.
- `redir ... permanent` — ответ `301`: браузер запомнит, что настоящий адрес без `www`. `{uri}` сохраняет путь: `www.example.ru/login` → `example.ru/login`.
- Caddy получит **два** сертификата: на `example.ru` и на `www.example.ru`. Поэтому A-запись для `www` нужна (3.6).

Проверено через `caddy adapt`: конфиг разбирается, `www.example.ru` перенаправляется на `https://example.ru{uri}`.

<details><summary>Вопрос 13. Зачем строка с acme-staging, если она закомментирована?</summary>

У Let's Encrypt есть лимиты: например, не больше 5 неудачных проверок на одно имя за час. Если DNS ещё не обновился или порт 80 закрыт, Caddy будет пробовать снова и снова и быстро упрётся в лимит. Тогда даже после исправления придётся ждать.

Тестовый (staging) центр выдаёт ненастоящие сертификаты, но лимиты у него намного мягче. Порядок для первой выкатки или если что-то не получается:

1. Раскомментируй строку, выкати, смотри `docker compose logs caddy`.
2. Когда в логах `certificate obtained successfully`, всё настроено правильно (браузер покажет предупреждение — это ожидаемо для тестового сертификата).
3. Закомментируй строку обратно, выкати. Caddy получит настоящий сертификат.

Если первый же запуск прошёл гладко, можно обойтись без staging.
</details>

## 6. SSH-туннель к PostgreSQL

### 6.1. Что хотим и почему именно так

Хотим: открыть боевую базу в PyCharm или DBeaver, посмотреть таблицы, выполнить `SELECT`.

Как **нельзя**: открыть порт `5432` в интернет. Даже с паролем: базу начнут перебирать боты в первые часы, а любая уязвимость Postgres станет твоей проблемой.

Как **можно**: через SSH, который и так открыт и защищён ключом.

```text
PyCharm ──► 127.0.0.1:15432 (твой компьютер)
                │  SSH-туннель, всё зашифровано, порт 22
                ▼
           сервер ──► 127.0.0.1:5432 ──► контейнер pg_database
```

Три решения, которые мы принимаем, и почему:

1. **SSH под пользователем `jenifer`, а не `deploy`.** Ключ `deploy` без пароля, лежит в GitHub Secrets и даёт почти root-доступ через группу `docker` (вопрос 7 урока по деплою). Его используют только для деплоя. Для работы руками — твой личный ключ с паролем. Если ключ `deploy` придётся отозвать, твой доступ к базе не сломается, и наоборот.
2. **Отдельная роль в Postgres только для чтения**, а не главный пользователь из `.env`. Главный пользователь владеет всеми таблицами и может их удалить. В PyCharm одно неосторожное `DELETE` без `WHERE` или случайный клик «Drop» — и база пуста. Роль только для чтения такого не может физически.
3. **Локальный порт `15432`, а не `5432`.** На твоём компьютере `5432` уже занят домашней базой из `compose.yaml`.

### 6.2. Открыть порт базы на самом сервере (только для него)

Сейчас в `deploy/compose.prod.yaml` у `pg_database` нет `ports`. Значит, база доступна только из Docker-сети (`api` ходит к ней как `pg_database:5432`), а на самом сервере на `127.0.0.1:5432` никого нет, и туннелю некуда вести.

Задание: добавь `pg_database` порт, привязанный к `127.0.0.1` сервера, — так же, как уже сделано у `api` для `8000`.

<details><summary>Вопрос 16. В уроке по деплою было правило «у базы на сервере нет ports вообще». Почему теперь можно?</summary>

Правило было против `"5432:5432"` — без адреса впереди. Такая запись открывает порт на **всех** адресах сервера, включая публичный, и Docker делает это в обход ufw.

С `127.0.0.1:` впереди порт слушает только сам сервер. Из интернета до него не достать, а через SSH-туннель — можно, потому что туннель «выходит» на самом сервере. Это ровно то же, что уже сделано у `api`.

Проверка после выкатки, на сервере:

```bash
sudo ss -tlnp | grep 5432
```

Должно быть `127.0.0.1:5432`. Если видишь `0.0.0.0:5432` или `*:5432` — порт открыт в интернет, немедленно исправь.

И снаружи, с твоего компьютера: `Test-NetConnection <IP> -Port 5432` → `TcpTestSucceeded : False`.
</details>

<details><summary>Вопрос 17. А можно вообще без ports? Туннель же может вести прямо в контейнер</summary>

Можно: у контейнера в Docker-сети есть свой IP (`sudo docker inspect` покажет что-то вроде `172.18.0.3`), и туннель `-L 15432:172.18.0.3:5432` туда дойдёт. Но этот IP меняется при пересоздании контейнера, то есть почти при каждом деплое. Каждый раз искать новый IP и перенастраивать PyCharm — неудобно. `127.0.0.1:5432` стабилен.

Есть и третий путь, совсем без туннеля: `sudo docker compose exec pg_database psql ...` прямо на сервере. Он отлично подходит для разовой команды, но без удобства PyCharm.
</details>

Выкати это обычным путём: коммит в `dev` → CI → merge в `main`.

### 6.3. Роль «только чтение»

Это делается **один раз руками на сервере**, а не через init-скрипты: init-скрипты выполняются только на пустой базе, а пароль роли не должен лежать в git.

Зайди в `psql` главным пользователем. Переменные `POSTGRES_USER` и `POSTGRES_DB` есть внутри контейнера, поэтому команда в одинарных кавычках:

```bash
cd /opt/fastapi-train
sudo docker compose exec pg_database sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
```

Дальше SQL. Имя роли придумай сам, но **не начинай его с `pg_`**: такие имена Postgres резервирует для служебных ролей и не даст создать (ты уже встречал это при первом деплое). Ниже имя `jenifer_ro`, а имя базы подставь своё — оно в `POSTGRES_SETTINGS__DATABASE`.

```sql
CREATE ROLE jenifer_ro LOGIN;
\password jenifer_ro
GRANT CONNECT ON DATABASE имя_базы TO jenifer_ro;
GRANT USAGE ON SCHEMA payment_statistic, logs TO jenifer_ro;
GRANT SELECT ON ALL TABLES IN SCHEMA payment_statistic, logs TO jenifer_ro;
ALTER DEFAULT PRIVILEGES IN SCHEMA payment_statistic, logs GRANT SELECT ON TABLES TO jenifer_ro;
ALTER ROLE jenifer_ro SET default_transaction_read_only = on;
```

Разбор по строкам:

| Строка | Что делает |
|---|---|
| `CREATE ROLE ... LOGIN` | Роль, которой можно подключаться. Без `LOGIN` это была бы просто «группа прав». |
| `\password jenifer_ro` | Команда `psql` (не SQL): спросит пароль дважды и отправит в базу уже **хеш**. Пароль не попадёт ни в историю `psql`, ни в логи Postgres. |
| `GRANT CONNECT` | Право подключиться к этой базе. |
| `GRANT USAGE ON SCHEMA` | Право «заходить» в схему. Без него `SELECT` скажет `permission denied for schema`, даже если права на таблицу есть. |
| `GRANT SELECT ON ALL TABLES` | Чтение всех **существующих** таблиц. |
| `ALTER DEFAULT PRIVILEGES` | Чтение таблиц, которые главный пользователь создаст **в будущем**. Без этой строки новая таблица окажется недоступна. |
| `default_transaction_read_only = on` | Второй замок: каждая транзакция этой роли по умолчанию только для чтения. |

Пароль сгенерируй длинный (`openssl rand -base64 24` на сервере) и сохрани в менеджер паролей. Выйди из `psql`: `\q`.

Проверено на PostgreSQL 18 с init-скриптами проекта: `SELECT` из `payment_statistic.users` работает, таблица, созданная после `ALTER DEFAULT PRIVILEGES`, читается, `UPDATE` получает `cannot execute UPDATE in a read-only transaction`, а после `SET default_transaction_read_only = off` — `permission denied for table users`. `CREATE TABLE` — `permission denied for schema logs`.

<details><summary>Вопрос 18. Зачем два замка? GRANT SELECT же и так не даёт писать</summary>

Первый замок (только `SELECT` в правах) защищает **таблицы**. Второй (`read_only`) — запасной на случай ошибки в первом: например, через год ты по невнимательности выдашь роли `INSERT` на какую-то таблицу «на минутку» и забудешь. Каждый замок можно сломать, оба сразу — маловероятно.

Замок `read_only` — не настоящая защита: роль может сама его выключить командой `SET` (что и показала проверка). Он защищает от **случайности**, а не от злоумышленника. От злоумышленника защищают права.
</details>

<details><summary>Вопрос 19. Роль только для чтения видит password_hash и user_sessions. Это проблема?</summary>

Для тебя — нет: это твоя база. Но помни, что через эту роль видны хеши паролей и хеши токенов сессий. Значит:

- не выкладывай скриншоты таблиц `users` и `user_sessions` в чаты;
- если когда-нибудь дашь доступ к базе кому-то ещё (аналитику), ему нужна другая роль, которой выданы права на отдельные столбцы или на представления (`VIEW`) без этих столбцов. Это задание уровня 6 тренировки.
</details>

### 6.4. Туннель из PowerShell и проверка через psql

Открой туннель в отдельном окне PowerShell:

```powershell
ssh -N -L 15432:127.0.0.1:5432 fastapi
```

Окно «зависнет» — так и надо. Проверка во втором окне:

```powershell
Test-NetConnection 127.0.0.1 -Port 15432
```

`TcpTestSucceeded : True` — туннель слушает. Если у тебя установлен `psql` (он ставится вместе с PostgreSQL для Windows, галочка «Command Line Tools»):

```powershell
psql -h 127.0.0.1 -p 15432 -U jenifer_ro -d имя_базы -c "select id, name from payment_statistic.users"
```

Если `psql` нет — переходи сразу к PyCharm или DBeaver, это не обязательный шаг.

Можно не держать отдельное окно: в `C:\Users\Jenifer\.ssh\config` добавь хост именно для базы:

```text
Host fastapi-db
    HostName example.ru
    User jenifer
    IdentityFile ~/.ssh/id_ed25519
    LocalForward 15432 127.0.0.1:5432
    ServerAliveInterval 30
    ServerAliveCountMax 3
```

и запускай `ssh -N fastapi-db`. `LocalForward` — то же самое, что `-L`, только в конфиге.

### 6.5. PyCharm

Вкладка **Database** есть в PyCharm с подпиской (бывший Professional). Если у тебя её нет, переходи к DBeaver (6.6): он бесплатный.

PyCharm умеет сам открывать туннель, отдельное окно PowerShell тогда не нужно.

1. **Database** (справа) → **+** → **Data Source** → **PostgreSQL**.
2. Вкладка **SSH/SSL** → галочка **Use SSH tunnel** → **...** рядом с конфигурацией → **+**:
   - **Host:** `example.ru` (или IP), **Port:** `22`, **Username:** `jenifer`;
   - **Authentication type:** `Key pair`;
   - **Private key file:** `C:\Users\Jenifer\.ssh\id_ed25519`, **Passphrase:** пароль от ключа;
   - **Test Connection** → должен сказать «Successfully connected».
3. Вкладка **General**:
   - **Host:** `localhost`, **Port:** `5432` — **с точки зрения сервера**, как в `-L ...:127.0.0.1:5432`. Порт `15432` здесь не нужен: PyCharm сам выберет локальный порт для своего туннеля;
   - **User:** `jenifer_ro`, **Password:** пароль роли;
   - **Database:** имя базы.
4. **Test Connection**. Если PyCharm предложит скачать драйвер — соглашайся.
5. Вкладка **Options** → галочка **Read-only**. Третий замок: PyCharm сам не даст запустить изменяющий запрос.
6. Дай подключению имя вроде `PROD fastapi (read-only)` и в **General** выбери цвет (красный). Так боевую базу невозможно спутать с домашней.

<details><summary>Вопрос 20. Почему во вкладке General стоит 5432, а в PowerShell был 15432?</summary>

В PowerShell туннель открываешь ты, и ты сам выбираешь, какой порт он займёт на твоём компьютере (`15432`). PyCharm в режиме **Use SSH tunnel** открывает туннель сам и сам выбирает свободный локальный порт. Ты сообщаешь ему только конечную точку **на сервере**: `localhost:5432`.

Если же туннель уже открыт вручную в PowerShell, можно не включать **Use SSH tunnel**, а указать в **General** `localhost:15432`. Работают оба способа, просто не смешивай их в одном подключении.
</details>

### 6.6. DBeaver

DBeaver Community — бесплатный, ставится с dbeaver.io.

1. **Database** → **New Database Connection** → **PostgreSQL**.
2. Вкладка **Main:** **Host** `localhost`, **Port** `5432`, **Database** имя базы, **Username** `jenifer_ro`, **Password** пароль роли.
3. Вкладка **SSH** → **Use SSH Tunnel**:
   - **Host/IP** `example.ru`, **Port** `22`, **User Name** `jenifer`;
   - **Authentication Method:** `Public Key`, **Private Key:** `C:\Users\Jenifer\.ssh\id_ed25519`, **Passphrase:** пароль от ключа.
4. **Test Connection**. DBeaver предложит скачать драйвер — соглашайся.
5. В настройках подключения (**General**) выбери **Connection type: Production** и включи **Read-only connection**. DBeaver станет подсвечивать окно красным и спрашивать подтверждение перед изменениями.

Логика портов та же, что у PyCharm: в **Main** — адрес с точки зрения сервера.

## 7. Ловушки

### Цена первого года вместо цены продления
Домен за 169 ₽ может продлеваться за 1200 ₽. Через год ты либо платишь, либо переезжаешь к другому регистратору (это возможно, но хлопотно). Смотри на продление.

### Нет двухфакторной аутентификации у регистратора
Кто вошёл в кабинет регистратора, тот поменяет A-запись на свой сервер и получит на него сертификат. Твой сайт с твоей страницей входа окажется у чужого человека. 2FA обязательна.

### Домен истёк
Сайт перестаёт открываться, а через некоторое время домен освобождается. Автопродление или напоминание в календаре.

### Записи регистратора «по умолчанию» не удалены
Две `A`-записи на `@` (твоя и парковки) — и браузер ходит то на твой сервер, то на заглушку. Caddy получает сертификат через раз. В панели DNS должна остаться ровно одна `A` на имя.

### `AAAA` без работающего IPv6
Сертификат не выпускается, часть посетителей не открывает сайт. Без уверенности — без `AAAA`.

### Большой TTL перед переездом
Поставил TTL 86400, а потом сменил сервер — у части людей сутки открывается старый. Держи 300, пока всё не устоялось.

### Сертификат запрашивается до того, как обновился DNS
Caddy стучится в Let's Encrypt, тот идёт по старому адресу (или никуда) и получает ошибку. Пять неудач за час — и ждать. Сначала `Resolve-DnsName` через два DNS-сервера, потом выкатка. Или staging (5.2).

### `SITE_DOMAIN=https://example.ru`
Caddy ждёт имя, а не адрес. В `.env` — только `example.ru`.

### Проверка входа без обновления страницы
Вход «работает», а после `F5` выкидывает на `/login`. Почти всегда это cookie `Secure` по `http://` или `APP_ENV` не задан. Проверяй обновлением (вопрос 15).

### Пароль для входа без ограничения длины
Один бот с паролями по мегабайту занимает весь процессор argon2. `max_length` у `LoginIn` (4.1).

### 500 вместо 401 для пользователя без пароля
Посторонний по коду ответа узнаёт, что такой логин есть. Пустой хеш = как будто пользователя нет (4.2).

### `"5432:5432"` в боевом compose
Без `127.0.0.1:` база открыта в интернет в обход ufw. Проверка — `sudo ss -tlnp | grep 5432`.

### Локальный порт туннеля `5432`
На твоём компьютере `5432` занят домашней базой. В лучшем случае ssh скажет `bind: Address already in use`. В худшем (Docker и ssh слушают разные адреса) PyCharm молча подключится к **домашней** базе, и ты будешь удивляться, куда делись боевые чеки. Для туннеля — `15432`.

### Туннель под `deploy`
Ключ `deploy` — для GitHub Actions. Использовать его руками — значит хранить его копию у себя в удобном месте и тренировать привычку ходить на сервер «под root». Под `jenifer`.

### Главный пользователь базы в PyCharm
Один клик «Drop table» или `DELETE` без `WHERE` — и данных нет. Для просмотра — роль только для чтения (6.3), а изменения схемы — через init-скрипты и миграции, руками только с бэкапом.

### Пароль роли в `CREATE ROLE ... PASSWORD '...'`
Попадёт в историю `psql` (`~/.psql_history` в контейнере) и, при некоторых настройках, в лог Postgres. `\password` отправляет только хеш.

### В PyCharm в General стоит `15432` при включённом SSH-туннеле
PyCharm откроет туннель на сервер и попробует там подключиться к `localhost:15432`, где никого нет: `Connection refused`. При встроенном туннеле в General — порт **на сервере**, `5432`.

## 8. Диагностика: сначала найди этап

### Домен и DNS

| Симптом | Где смотреть | Частая причина |
|---|---|---|
| `Resolve-DnsName example.ru -Type NS` пусто или ошибка | Кабинет регистратора | Домен ещё не делегирован, или не прошла идентификация через Госуслуги |
| NS есть, `A` нет | Панель DNS | Запись не создана или создана в другой «зоне» кабинета |
| `A` разный у `1.1.1.1` и `8.8.8.8` | Подожди TTL | Запись обновилась не везде |
| `A` правильный, у тебя открывается старое | `ipconfig /flushdns` | Кеш Windows или роутера |

### Сайт

| Симптом | Где смотреть | Частая причина |
|---|---|---|
| Браузер: «сайт недоступен» | `sudo docker compose ps` | `caddy` не запущен, или не открыты 80/443 |
| Ошибка сертификата | `sudo docker compose logs caddy` | DNS ещё не указывает на сервер, `AAAA` без IPv6, закрыт порт 80, включён staging |
| `502 Bad Gateway` на всей странице | `logs web` | `web` не стартовал или упал |
| Страница есть, вход: «Сервер не отвечает» | `logs web`, F12 → Network | `api` лежит или `API_PROXY_TARGET` запечён как `127.0.0.1` |
| Вход проходит, после `F5` выкидывает | F12 → Application → Cookies | Сайт открыт по `http://`, или `APP_ENV` не `prod` при открытии по IP |
| `www.example.ru` не открывается | `logs caddy` | Нет `A` для `www` или нет блока `www.` в Caddyfile |

Команды на сервере (`cd /opt/fastapi-train`):

```bash
sudo docker compose ps
sudo docker compose logs --tail=50 caddy
sudo docker compose logs --tail=50 web
sudo docker compose logs --tail=50 api
curl -I https://example.ru/login
```

### Туннель и база

| Симптом | Где | Причина |
|---|---|---|
| `ssh: connect to host ... port 22: Connection timed out` | Сеть | Неправильный IP/домен, либо сервер выключен |
| `Permission denied (publickey)` | Ключ | Не тот ключ в `IdentityFile` или не тот пользователь |
| `bind [127.0.0.1]:15432: Address already in use` | Локально | Туннель уже открыт в другом окне или порт занят |
| `Test-NetConnection 127.0.0.1 -Port 15432` — False | Окно туннеля | Туннель не открыт или закрылся (окно закрыто, сон ноутбука) |
| `channel 2: open failed: connect failed: Connection refused` в окне ssh | Сервер | У `pg_database` нет `127.0.0.1:5432` в `ports`, или контейнер не запущен |
| `password authentication failed for user "jenifer_ro"` | Postgres | Не тот пароль роли, или роль создана в другой базе/сервере |
| `permission denied for schema ...` | Права | Нет `GRANT USAGE ON SCHEMA` |
| `permission denied for table ...` у новой таблицы | Права | Таблица создана до `ALTER DEFAULT PRIVILEGES` или другим пользователем: выдай `GRANT SELECT` на неё вручную |
| Видишь не те данные | PyCharm | Подключился к домашней базе: проверь порт и цвет подключения |

Проверка на сервере, что база слушает именно там, где должна:

```bash
sudo ss -tlnp | grep 5432
```

### Уровень 4. Ограничение попыток входа
Argon2 медленный, но бот всё равно может перебирать пароли сутками. Где хранить счётчик: в памяти процесса (словарь) или в таблице? Подумай, что будет со словарём при перезапуске `api` и почему для одного процесса это приемлемо. Не забудь сообщение для `429` в `login.vue`.

В `/home/deploy/.ssh/authorized_keys` перед ключом можно написать ограничения. Проверь, что деплой из GitHub Actions по-прежнему проходит, а туннель `ssh -N -L 15432:127.0.0.1:5432 -i ...fastapi_train_deploy deploy@...` — нет. Объясни, от чего это защищает.

### Уровень 6. Роль для аналитика
Создай роль `analyst_ro`, которая видит `receipt`, `receipt_compound`, `groups`, а у `users` — только `id` и `name`, и совсем не видит `user_sessions`. Подсказка: `GRANT SELECT (id, name) ON payment_statistic.users TO ...`. Проверь, что `SELECT * FROM payment_statistic.users` получает отказ, а `SELECT id, name` — нет.

### Уровень 8. Перенос навыка
