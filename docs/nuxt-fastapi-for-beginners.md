# Свой фронтенд на Nuxt к FastAPI для чайников 😄

**Цель урока:** после него ты пишешь Nuxt-страницу, которая показывает, создаёт и удаляет данные через FastAPI, **с пустого файла**, без копирования шаблона, и можешь объяснить каждую строку — и на фронтенде, и на бэкенде.

Урок построен на этом репозитории: бэкенд — `app/main.py` (пользователи в памяти), фронтенд ты создашь сам в папке `frontend/`. Команды выполняются **из корня репозитория**, если не сказано иное, и одинаково работают в PowerShell и в Linux shell. Код урока проверен на Nuxt 4.6, Vue 3.5, FastAPI 0.141, Node.js 22.

## 0. Как проходить урок

Правила те же, что в [уроке по Docker](docker-for-beginners.md):

1. **Печатай руками.** Не копируй блоки кода из урока в файлы. Опечатки и ошибки — часть обучения.
2. **Одна возможность — одна проверка.** Страница собирается по шагам; после каждого шага ты открываешь браузер и проверяешь, что появилось именно то, что ожидал.
3. **Сначала предскажи — потом запусти.** Перед каждой проверкой скажи себе, что должно произойти. Расхождение с реальностью — самое ценное место урока.
4. **Ответы — в свёрнутых блоках.** Открывай их только после своей попытки.

И одно новое правило:

5. **Держи открытыми два терминала и вкладку Network.** В одном работает FastAPI, в другом Nuxt, в браузере открыты инструменты разработчика (F12) на вкладке **Network**. Любой вопрос «почему не работает» начинается с того, что ты смотришь в эти три места.

План: понять модель (разделы 1–2) → пройти сценарий руками через Swagger (3–4) → подготовить бэкенд (5) → собрать страницу по шагам (6) → выучить правила, на которых все ошибаются (7) → диагностика (8) → тренировка с нарастающей сложностью (9) → повторение по памяти (10).

## 1. Что именно мы создаём

Получится **два отдельных приложения**, которые общаются по HTTP:

| Часть | Что это | Где работает | Порт |
|---|---|---|---|
| Бэкенд (FastAPI) | API: принимает HTTP-запросы, хранит и отдаёт данные в JSON | Python-процесс Uvicorn | 8000 |
| Фронтенд (Nuxt) | Сайт: страницы, кнопки, формы; за данными ходит в API | Node.js-сервер **и** браузер | 3000 |
| Vue-компонент (`.vue`) | Кусок интерфейса: шаблон (HTML) + логика (TypeScript) | Там же, где фронтенд | — |
| Страница | Компонент из папки `pages/`, у которого есть адрес (URL) | Там же | — |

**FastAPI отвечает на вопрос «какие данные и по каким правилам?». Nuxt отвечает на вопрос «как их показать и как человеку их изменить?».**

Схема запросов:

```text
Браузер ──(страница)──> Nuxt :3000
   │                       │
   │                       └──(GET /users при первой загрузке)──> FastAPI :8000
   │
   └──(POST, DELETE, PUT, повторный GET после нажатия кнопок)───> FastAPI :8000
```

Ещё три факта, которые понадобятся дальше:

- **Код страницы Nuxt выполняется в двух местах.** При открытии страницы Nuxt-сервер выполняет её код и присылает браузеру готовый HTML с данными (это SSR — server-side rendering). Потом тот же код запускается в браузере и «оживляет» страницу: кнопки начинают работать (это гидратация). Всё, что происходит после нажатий, происходит уже в браузере.
- **Браузер защищает пользователя.** Страница с адреса `http://localhost:3000` не может просто так читать ответы от `http://127.0.0.1:8000` — это другой «источник» (origin). Бэкенд должен явно разрешить это заголовками CORS. Запросы с Nuxt-сервера, из `curl` и из Swagger это правило не касается: его соблюдает только браузер.
- **Бэкенд ничего не знает о фронтенде.** Ему всё равно, кто прислал запрос: Swagger, `curl` или Nuxt. Поэтому всё, что ты умеешь сделать в Swagger, ты умеешь сделать и из Nuxt — нужно только правильно перевести запрос.

### Как это выглядит в реальной работе

Бэкенд и фронтенд обычно живут в одном репозитории в соседних папках (как у нас: `app/` и `frontend/`) или в двух разных репозиториях. Договорённость между ними — это **контракт API**: список эндпоинтов, их параметров и ответов. FastAPI сам публикует его в Swagger (`/docs`), поэтому фронтенд пишут, держа Swagger открытым в соседней вкладке. На сервере оба приложения обычно запускаются в Docker-контейнерах (уровень 8 тренировки).

## 2. Алгоритм: семь вопросов перед любым экраном

Страницу не пишут «сверху вниз по памяти». Её пишут, **ответив на вопросы о данных и действиях пользователя**. Запомни эти семь вопросов — это и есть навык:

1. Какие данные показываю или меняю и как они выглядят? → `type` в TypeScript (по схеме из Swagger)
2. Какой эндпоинт за это отвечает: метод и URL? → `method`, адрес запроса
3. Где параметры: в пути, в query string или в теле? → `` `/users/${id}` ``, `query: {...}`, `body: {...}`
4. Когда делать запрос: при открытии страницы или по действию пользователя? → `useFetch` или `$fetch`
5. Что видит пользователь, пока ждёт, и что — при ошибке? → `pending`, `error`, `try/catch`
6. Что должно обновиться на экране после изменения? → `refresh()`
7. С какого адреса на какой идёт запрос и пустит ли бэкенд? → `runtimeConfig`, CORS

Ответы для экрана «Список пользователей» нашего проекта:

| Вопрос | Ответ |
|---|---|
| Данные | `User`: `id` (число), `name` (строка), `age` (число), `description` (строка или `null`) |
| Эндпоинты | Список — `GET /users`; создать — `POST /create_user`; удалить — `DELETE /users/delete/{user_id}` |
| Параметры | Создание: `name`, `age`, `description` — в **query string**; удаление: `user_id` — в **пути** |
| Когда | Список — при открытии страницы (`useFetch`); создание и удаление — по кнопке (`$fetch`) |
| Ожидание и ошибки | «Загрузка…», текст ошибки загрузки, сообщение «Не удалось создать» |
| Что обновить | После создания и удаления — заново загрузить список |
| Адреса | Фронтенд `http://localhost:3000` → API `http://127.0.0.1:8000`; нужен CORS для `http://localhost:3000` |

Где брать ответы на вопросы 1–3, если код бэкенда писал не ты: **из Swagger**. Там у каждого эндпоинта видно метод, путь, раздел Parameters (в нём для каждого параметра указано `path` или `query`), раздел Request body (тело) и схему ответа.

> **Проверь себя.** Как по сигнатуре функции в `main.py` понять, что параметр `name` у `create_user` передаётся в query string, а `user_id` у `delete_user` — в пути?
>
> <details><summary>Ответ</summary>`user_id` упомянут в пути декоратора: `@app.delete("/users/delete/{user_id}")` — значит, он берётся из пути. `name: str` — простой тип (строка, число), которого нет в пути, — FastAPI берёт такие параметры из query string. Если бы тип параметра был Pydantic-моделью (`data: UserCreate`), FastAPI ждал бы JSON в теле запроса.</details>

## 3. Подготовь инструменты

Нужны Python 3.12+ (для бэкенда) и Node.js 20 или новее (для Nuxt). Установка Node.js: [nodejs.org](https://nodejs.org/) — бери версию LTS.

```sh
python --version
node --version
npm --version
```

**Ожидаемый результат:** `Python 3.12.x` или новее, `v20.x` или новее, номер версии npm. Если `node` не найден — после установки Node.js перезапусти терминал.

**Запусти бэкенд в первом терминале.** Из корня репозитория:

```sh
python -m venv .venv
```

Активируй окружение: в PowerShell `.venv\Scripts\Activate.ps1`, в Linux/macOS `source .venv/bin/activate`. Затем:

```sh
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --reload
```

**Ожидаемо:** `Uvicorn running on http://127.0.0.1:8000`. Открой [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs) — это Swagger.

`--reload` перезапускает сервер при каждом сохранении `.py`-файла. Этот терминал не закрывай до конца урока.

> Если ты прошёл урок по Docker, можно запускать бэкенд через `docker compose up --build`. Но тогда после каждой правки `main.py` пересобирай образ (`docker compose up -d --build`), иначе правки не попадут в контейнер.

## 4. Шаг ноль: пройди сценарий руками через Swagger

Это главный приём для написания фронтенда с нуля. **Страница — это записанная последовательность запросов, которые ты бы сделал руками в Swagger, плюс отображение их результата.** Поэтому сначала сделай их руками.

В Swagger выполни через **Try it out** по порядку и **запиши для каждого действия: метод, URL, где параметры, что пришло в ответ**:

1. `GET /users` — получить список. Что пришло?
2. `POST /create_user` — создать пользователя `Anna`, 30 лет, без описания.
3. Снова `GET /users`.
4. `POST /create_user` — создать пользователя, введя в `age` слово `abc`.
5. `DELETE /users/delete/{user_id}` — удалить Anna.
6. `DELETE /users/delete/{user_id}` — удалить её ещё раз.

> **Предскажи до запуска:** что вернут шаги 1, 4 и 6?
>
> <details><summary>Ответ</summary>
>
> 1. `[]` — пустой список: пользователи живут в памяти процесса, после старта их нет.
> 4. Статус **422** и JSON с `detail`, где сказано, что `age` должно быть целым числом. 422 — это FastAPI говорит «запрос не подходит под сигнатуру функции»; сама функция даже не вызывалась.
> 6. Статус **404** и `{"detail": "User not found"}` — это `raise HTTPException(status_code=404, ...)` из `main.py`.
>
> </details>

Посмотри на поле **Curl** под каждым ответом в Swagger: это точный HTTP-запрос. Например:

```text
curl -X 'POST' 'http://127.0.0.1:8000/create_user?name=Anna&age=30' -H 'accept: application/json' -d ''
```

Параметры стоят после `?` — это и есть query string. Тела запроса нет (`-d ''`).

Запиши свои ручные действия — **следующие разделы превращают каждое из них в код**:

| Ручное действие в Swagger | Код в Nuxt |
|---|---|
| Открыть страницу и сразу нажать `GET /users` | `useFetch('/users', ...)` |
| Посмотреть на JSON со списком | `<li v-for="user in users">` |
| Заполнить `name`, `age`, `description` | `<input v-model="name">` и т. д. |
| Нажать Execute у `POST /create_user` | `$fetch('/create_user', { method: 'POST', query: {...} })` |
| Снова нажать `GET /users`, чтобы увидеть результат | `refresh()` |
| Нажать Execute у `DELETE /users/delete/{id}` | `$fetch(`` `/users/delete/${id}` ``, { method: 'DELETE' })` |
| Увидеть 404 или 422 | `try/catch`, `error` |

Разница одна: Swagger открыт на том же адресе, что и API (`127.0.0.1:8000`), а твоя страница будет на другом (`localhost:3000`). Поэтому понадобится ещё одно действие на бэкенде — раздел 5.

## 5. Готовим бэкенд: разрешаем фронтенду ходить в API

Браузер выполняет запросы со страницы `http://localhost:3000` к `http://127.0.0.1:8000` только если API в ответ скажет «этому источнику можно». Это делает middleware CORS. Отдельно устанавливать ничего не нужно — он входит в FastAPI.

Открой `app/main.py`. Допиши импорт к остальным импортам вверху:

```python
from fastapi.middleware.cors import CORSMiddleware
```

И сразу после строки `app = FastAPI()`:

```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:3000"],
    allow_methods=["*"],
    allow_headers=["*"],
)
```

- `allow_origins` — с каких адресов страницы **можно** обращаться к API из браузера. Origin — это схема + хост + порт: `http://localhost:3000` и `http://127.0.0.1:3000` — **разные** origin.
- `allow_methods=["*"]` — разрешить любые методы (`GET`, `POST`, `PUT`, `DELETE`).
- `allow_headers=["*"]` — разрешить любые заголовки, например `Content-Type: application/json`, без которого не отправить JSON-тело.

Сохрани файл: Uvicorn с `--reload` перезапустится сам.

Проверь из терминала (в PowerShell пиши `curl.exe` вместо `curl`):

```sh
curl -i -H "Origin: http://localhost:3000" http://127.0.0.1:8000/users
```

**Ожидаемо:** среди заголовков ответа есть `access-control-allow-origin: http://localhost:3000`.

> Не пиши `allow_origins=["*"]` «чтобы точно заработало». Так ты разрешишь любому сайту в интернете из браузера твоего пользователя обращаться к API. Перечисляй адреса фронтенда явно.

Почему мы не увидели проблему раньше и когда CORS вообще срабатывает — разберём в разделе 7. Там же есть эксперимент: что будет, если CORS убрать.

## 6. Собираем страницу по одной возможности

На каждом шаге цикл одинаковый: **дописал → сохранил → посмотрел в браузер и на вкладку Network**.

### Шаг 1. Пустой проект Nuxt

Во **втором терминале**, из корня репозитория:

```sh
npm create nuxt@latest frontend
```

Мастер задаст вопросы. Отвечай так:

| Вопрос | Ответ | Почему |
|---|---|---|
| Шаблон (template) | `minimal` | Минимум файлов: всё остальное напишешь сам |
| Менеджер пакетов | `npm` | Уже установлен вместе с Node.js |
| Инициализировать git-репозиторий | `No` | Репозиторий уже есть, вложенный не нужен |
| Дополнительные модули | ничего не выбирать | Не нужны для урока |

Затем:

```sh
cd frontend
npm run dev
```

**Ожидаемо:** строка `Local: http://localhost:3000/`, а по этому адресу — приветственная страница Nuxt. С этого момента второй терминал занят Nuxt; команды `npm` для фронтенда выполняй из папки `frontend/`.

Посмотри, что создалось:

| Файл | Зачем |
|---|---|
| `package.json` | Список зависимостей (`nuxt`, `vue`) и скриптов (`dev`, `build`) — аналог `requirements.txt` |
| `package-lock.json` | Точные версии всех установленных пакетов. Коммитится в git |
| `node_modules/` | Сами пакеты — аналог `.venv`. **Не коммитится** (уже есть в `frontend/.gitignore`) |
| `nuxt.config.ts` | Настройки Nuxt |
| `app/app.vue` | Корневой компонент: с него начинается любая страница |
| `.nuxt/`, `.output/` | Сгенерированные файлы. Не трогай и не коммить |

> **Предскажи:** что будет, если удалить `node_modules` и снова запустить `npm run dev`? Как это исправить?
>
> <details><summary>Ответ</summary>Ошибка: команда `nuxt` не найдена — пакетов нет. Исправление — `npm install`: он установит всё по `package.json` и `package-lock.json`. Именно поэтому `node_modules` не хранят в git: его всегда можно восстановить.</details>

### Шаг 2. Своя страница — `app.vue` и `pages/`

Замени содержимое `app/app.vue` целиком:

```vue
<template>
  <NuxtPage />
</template>
```

Создай файл `app/pages/index.vue`:

```vue
<template>
  <main>
    <h1>Пользователи</h1>
  </main>
</template>
```

- `<NuxtPage />` — место, куда Nuxt подставляет текущую страницу из папки `pages/`.
- **Маршрут = путь к файлу.** `pages/index.vue` → адрес `/`; `pages/about.vue` → `/about`; `pages/users/[id].vue` → `/users/5`, `/users/42` и т. д. Таблицу маршрутов писать не нужно.

**Ожидаемо:** на `http://localhost:3000` — заголовок «Пользователи».

> **Предскажи:** что будет на `http://localhost:3000/about`?
>
> <details><summary>Ответ</summary>Страница ошибки 404 от Nuxt: файла `pages/about.vue` нет, значит, нет и маршрута. Создай его с любым заголовком — адрес заработает без перезапуска.</details>

### Шаг 3. Адрес API в настройках — `runtimeConfig`

Адрес бэкенда не вписывают в каждую страницу: он разный на твоём компьютере и на сервере. Его кладут в настройки. Приведи `nuxt.config.ts` к виду:

```ts
export default defineNuxtConfig({
  compatibilityDate: '2025-07-15',
  devtools: { enabled: true },
  nitro: {
    externals: { inline: [/[\\/]node_modules[\\/]nuxt[\\/]dist[\\/]/] },
  },
  runtimeConfig: {
    public: {
      apiBase: 'http://127.0.0.1:8000',
    },
  },
})
```

(Строку `compatibilityDate` оставь такой, какую создал мастер.)

> **Блок `nitro` — заплатка для Windows, а не часть урока.** В Nuxt 4.6.0 на Windows любая страница отдаёт ошибку 500 `Either manifest or precomputed data must be provided` ([баг Nuxt #36467](https://github.com/nuxt/nuxt/issues/36467)). Эта строка обходит его; на Linux и macOS она ничего не меняет. Запоминать её не нужно. Когда выйдет версия Nuxt с исправлением, блок можно удалить.

- `runtimeConfig` — настройки, которые можно поменять **при запуске**, без пересборки, через переменные окружения. Значение `public.apiBase` заменяется переменной `NUXT_PUBLIC_API_BASE`.
- `public` — эти настройки попадут в браузер. Всё, что лежит в `runtimeConfig` **вне** `public`, видно только Nuxt-серверу: туда кладут секреты.
- `127.0.0.1`, а не `localhost`: Uvicorn по умолчанию слушает только `127.0.0.1` (IPv4), а `localhost` на некоторых системах сначала превращается в IPv6-адрес `::1`, где никто не слушает.

Проверь, что настройка читается. Добавь в начало `pages/index.vue` блок скрипта:

```vue
<script setup lang="ts">
const config = useRuntimeConfig()
console.log('apiBase =', config.public.apiBase)
</script>
```

> **Предскажи до обновления страницы:** где появится строка `apiBase = ...` — в терминале Nuxt или в консоли браузера (F12 → Console)?
>
> <details><summary>Ответ</summary>В **обоих** местах. Сначала код страницы выполнился на Nuxt-сервере (SSR) — строка в терминале. Потом тот же код выполнился в браузере при гидратации — строка в консоли браузера. Запомни это: код в `<script setup>` страницы работает и на сервере, и в браузере.</details>

После проверки удали `console.log`.

- `<script setup lang="ts">` — логика компонента на TypeScript. Всё, что объявлено здесь, доступно в `<template>`.
- `useRuntimeConfig`, `useFetch`, `ref` и другие функции Nuxt и Vue **не нужно импортировать** — Nuxt подключает их автоматически.

### Шаг 4. Загрузка списка — `useFetch`, `v-for`, `v-if`

Ответы на вопросы 1, 4 и 5: данные — массив `User`, загружаем при открытии страницы, показываем загрузку и ошибку.

Создай файл с типом `app/types/user.ts` — он понадобится в нескольких местах:

```ts
export type User = {
  id: number
  name: string
  age: number
  description: string | null
}
```

Это **копия схемы `User` из `main.py`** на языке TypeScript. Сверь поля: Python `int` → `number`, `str` → `string`, `str | None` → `string | null`.

Скрипт страницы `pages/index.vue` теперь:

```vue
<script setup lang="ts">
import type { User } from '~/types/user'

const config = useRuntimeConfig()
const apiBase = config.public.apiBase

const { data: users, pending, error, refresh } = await useFetch<User[]>('/users', {
  baseURL: apiBase,
})
</script>
```

- `~` — это папка `app/`. `~/types/user` = `app/types/user.ts`.
- `useFetch` делает GET-запрос **при открытии страницы** и возвращает объект с полями. `{ data: users, ... }` — достаём поле `data` и называем его `users`.
- `data` — ответ сервера; `pending` — `true`, пока запрос идёт; `error` — ошибка или `null`; `refresh` — функция «загрузи заново».
- `<User[]>` — подсказка для TypeScript: «в ответе массив пользователей». На то, что реально пришлёт сервер, она не влияет.
- `baseURL` + `'/users'` = `http://127.0.0.1:8000/users`.
- `await` нужен, чтобы при SSR Nuxt дождался данных и отдал браузеру HTML уже со списком.

Шаблон под скриптом:

```vue
<template>
  <main>
    <h1>Пользователи</h1>

    <p v-if="pending">Загрузка…</p>
    <p v-else-if="error">Ошибка загрузки: {{ error.message }}</p>
    <p v-else-if="!users?.length">Пользователей пока нет</p>
    <ul v-else>
      <li v-for="user in users" :key="user.id">
        {{ user.name }}, {{ user.age }}
        <span v-if="user.description">— {{ user.description }}</span>
      </li>
    </ul>
  </main>
</template>
```

- `{{ ... }}` — вывести значение выражения в текст.
- `v-if` / `v-else-if` / `v-else` — показать **один** из элементов цепочки по условию. Порядок важен: сначала загрузка, потом ошибка, потом пустой список, потом сам список.
- `v-for="user in users"` — повторить `<li>` для каждого элемента массива.
- `:key="user.id"` — уникальный ключ элемента списка. Двоеточие перед атрибутом значит «значение — это выражение JavaScript, а не строка». Без ключа Vue путает элементы при обновлении списка.
- `users?.length` — `?.` не падает, если `users` ещё пустое (`undefined`).

**Проверь:** создай в Swagger двух пользователей, обнови страницу — они в списке. Посмотри на Network: найди запрос к `127.0.0.1:8000/users`.

> **Предскажи:** сколько запросов `GET /users` увидишь во вкладке Network при обновлении страницы? А в логе Uvicorn в первом терминале?
>
> <details><summary>Ответ</summary>В Network **ни одного** запроса к `:8000/users`, а в логе Uvicorn — **один**. Запрос сделал Nuxt-сервер при SSR и вложил данные прямо в HTML. Браузер при гидратации взял их оттуда, а не запрашивал повторно. Если открыть в Network сам документ `localhost` и посмотреть Response — увидишь имена пользователей прямо в HTML.</details>

Останови бэкенд (Ctrl+C в первом терминале) и обнови страницу. Что видно? Запусти бэкенд снова. Этот симптом пригодится в разделе 8.

### Шаг 5. Создание — `ref`, `v-model`, `$fetch`, `refresh`

Ответы на вопросы 2–4 и 6: `POST /create_user`, параметры в query string, запрос — по кнопке, после него обновить список.

Допиши в скрипт, под `useFetch`:

```ts
const name = ref('')
const age = ref(18)
const description = ref('')
const formError = ref('')

async function createUser() {
  formError.value = ''
  try {
    await $fetch('/create_user', {
      baseURL: apiBase,
      method: 'POST',
      query: {
        name: name.value,
        age: age.value,
        description: description.value || undefined,
      },
    })
    name.value = ''
    description.value = ''
    await refresh()
  } catch {
    formError.value = 'Не удалось создать пользователя'
  }
}
```

И в шаблон, после `<h1>`:

```vue
    <form @submit.prevent="createUser">
      <input v-model="name" placeholder="Имя" required>
      <input v-model.number="age" type="number" min="0" required>
      <input v-model="description" placeholder="Описание">
      <button type="submit">Создать</button>
    </form>
    <p v-if="formError">{{ formError }}</p>
```

- `ref('')` — **реактивная** переменная: когда её значение меняется, Vue сам перерисовывает всё, где она используется. В скрипте значение читают и пишут через `.value`; в шаблоне `.value` не пишут — Vue разворачивает сам.
- `v-model="name"` — двусторонняя связь: ввёл текст в поле → изменился `name`; изменил `name` в коде → изменилось поле. Так форма очищается строкой `name.value = ''`.
- `v-model.number` — превратить введённое в число. Без `.number` из поля всегда приходит строка.
- `@submit.prevent="createUser"` — `@` подписывается на событие. `.prevent` отменяет стандартное поведение формы (перезагрузку страницы).
- `$fetch` — **просто выполнить запрос** и вернуть ответ. При ответе 4xx/5xx он бросает исключение, поэтому `try/catch`.
- `query: {...}` — эти поля станут `?name=...&age=...` в URL, ровно как в Swagger. `undefined` в query не отправляется — поэтому пустое описание не уйдёт вовсе, и FastAPI подставит `None`.
- `await refresh()` — повторить запрос из `useFetch`, чтобы список обновился (вопрос 6).

**Проверь:** создай пользователя через форму. Во вкладке Network должен быть `POST create_user?name=...` со статусом 200, а сразу за ним — `GET users`.

> **Предскажи:** закомментируй строку `await refresh()` и создай пользователя. Что увидишь на странице и в Network? Что изменится после F5?
>
> <details><summary>Ответ</summary>В Network `POST` прошёл со статусом 200, но список на странице не изменился: страница не знает, что данные на сервере поменялись, пока не спросит заново. После F5 новый пользователь появится — значит, на сервере он был создан. Верни `refresh()`.</details>

### Шаг 6. Удаление и свой компонент — `props`, `emit`

Ответы на вопросы: `DELETE /users/delete/{user_id}`, параметр в **пути**, по кнопке, потом обновить список.

Допиши функцию в скрипт страницы:

```ts
async function deleteUser(id: number) {
  await $fetch(`/users/delete/${id}`, { baseURL: apiBase, method: 'DELETE' })
  await refresh()
}
```

Обратные кавычки `` ` `` — строка-шаблон: `${id}` подставляет значение в путь. Это и есть параметр **в пути**.

Строка списка разрастается — вынесем её в отдельный компонент. Создай `app/components/UserItem.vue`:

```vue
<script setup lang="ts">
import type { User } from '~/types/user'

defineProps<{ user: User }>()
const emit = defineEmits<{ delete: [id: number] }>()
</script>

<template>
  <li>
    {{ user.name }}, {{ user.age }}
    <span v-if="user.description">— {{ user.description }}</span>
    <button @click="emit('delete', user.id)">Удалить</button>
  </li>
</template>
```

И замени `<li v-for ...>...</li>` на странице одной строкой:

```vue
      <UserItem v-for="user in users" :key="user.id" :user="user" @delete="deleteUser" />
```

Главное правило компонентов: **данные идут вниз через props, события — вверх через emit.**

- `defineProps<{ user: User }>()` — компонент принимает свойство `user`. Страница передаёт его как `:user="user"`.
- `defineEmits<{ delete: [id: number] }>()` — компонент умеет сообщать о событии `delete` с числом. Сам он ничего не удаляет и про API не знает.
- `emit('delete', user.id)` — «меня попросили удалить вот этого». Страница слушает `@delete="deleteUser"` и вызывает свою функцию с этим числом.
- Компоненты из `app/components/` **не нужно импортировать**: `UserItem.vue` доступен как `<UserItem>` по имени файла.

**Проверь:** удали пользователя кнопкой. В Network — `DELETE users/delete/0`, затем `GET users`.

> **Предскажи:** почему бы не вызвать `$fetch` прямо в `UserItem.vue`? Что сломается или станет неудобно?
>
> <details><summary>Ответ</summary>Удалить из `UserItem` можно, но список живёт на странице, и обновить его (`refresh`) может только страница. Пришлось бы ещё как-то сообщать странице «я удалил» — то есть всё равно делать `emit`. Кроме того, компонент, который только показывает данные и сообщает о нажатиях, можно переиспользовать где угодно. Правило: запросы делает тот, кто владеет данными.</details>

## 7. Правила, на которых ошибаются при написании с нуля

### Где выполняется код: сервер Nuxt или браузер

| Что | Где выполняется |
|---|---|
| `<script setup>` страницы при открытии по адресу или F5 | Сначала на Nuxt-сервере, потом в браузере |
| `useFetch` при открытии страницы | На Nuxt-сервере; браузер получает готовые данные в HTML |
| Обработчики `@click`, `@submit` и всё, что они вызывают | Только в браузере |
| `refresh()` после нажатия кнопки | В браузере |
| Переход по `<NuxtLink>` на другую страницу | Код новой страницы — только в браузере |

Следствия:

- В `<script setup>` нельзя просто так обращаться к `window`, `document`, `localStorage` — на сервере их нет. Такой код кладут в обработчики событий или в `onMounted(() => { ... })` — он выполняется только в браузере.
- Запрос из `useFetch` при первой загрузке идёт **с сервера**, а запросы после кнопок — **из браузера**. Это два разных отправителя, у них могут быть разные проблемы (см. CORS ниже и уровень 8).

### `useFetch` против `$fetch`

| | `useFetch` | `$fetch` |
|---|---|---|
| Когда | Данные нужны при открытии страницы | Действие пользователя: кнопка, форма |
| Где писать | Верхний уровень `<script setup>` | Внутри функций-обработчиков |
| Что возвращает | `{ data, pending, error, refresh, ... }` — реактивные поля | Сам ответ сервера (или бросает исключение) |
| Повторный запрос при гидратации | Нет — данные передаются с сервера | — |
| Ошибка 4xx/5xx | Попадает в `error`, страница продолжает работать | Исключение — нужен `try/catch` |

Если вызвать `useFetch` внутри обработчика кнопки, Nuxt выведет в консоль предупреждение, а данные из него не будут обновлять шаблон так, как ты ждёшь. Если вызвать `$fetch` на верхнем уровне `<script setup>`, запрос выполнится **дважды** — на сервере и в браузере.

### `ref` и `.value`

```ts
const name = ref('')
name.value = 'Анна'   // в <script>: всегда через .value
```

```vue
{{ name }}             <!-- в <template>: без .value -->
```

Две частые ошибки:

- `name = 'Анна'` в скрипте — редактор подчеркнёт строку, а в браузере при выполнении будет ошибка `Assignment to constant variable`: `name` — это контейнер `ref`, его не заменяют, меняют его `.value`.
- `{{ users.value }}` в шаблоне — пусто: Vue уже развернул `users` в массив, а у массива нет поля `value`.

Ещё одна: обычная переменная `let count = 0` **не реактивна**. Её изменение не перерисует страницу. Всё, что меняется и показывается, — через `ref`.

### Как перевести параметры FastAPI в `$fetch`

Это главная таблица урока: она соединяет две половины приложения.

| В FastAPI (`main.py`) | В Swagger | В `$fetch` |
|---|---|---|
| `@app.post(...)`, `@app.get(...)`, `@app.put(...)`, `@app.delete(...)` | Цветная метка метода | `method: 'POST'` (для GET можно не писать) |
| `"/users/delete/{user_id}"` + `user_id: int` | Parameters → `path` | `` `/users/delete/${id}` `` |
| `name: str`, `age: int` (простой тип, нет в пути) | Parameters → `query` | `query: { name, age }` |
| `data: UserCreate` (Pydantic-модель) | Request body | `body: { name, age }` — `$fetch` сам превратит в JSON |
| `description: str \| None = None` | Параметр без `* required` | Можно не передавать (`undefined`) |
| `return ...` | Response body | То, что вернул `await $fetch(...)`, или `data` у `useFetch` |
| `raise HTTPException(404, ...)` | Код 404 | Исключение в `$fetch`; `error.value.statusCode === 404` в `useFetch` |
| Неверный тип или нет обязательного параметра | Код 422 и `detail` | Исключение; в Network → Response видно, какое поле не подошло |

> **Проверь себя.** В `main.py` есть `def update_user(user_id: int, age: int, name: str, description: str)` под `@app.put("/users/update/{user_id}")`. Напиши вызов `$fetch` для него.
>
> <details><summary>Ответ</summary>
>
> ```ts
> await $fetch(`/users/update/${id}`, {
>   baseURL: apiBase,
>   method: 'PUT',
>   query: { name: name.value, age: age.value, description: description.value },
> })
> ```
>
> `user_id` есть в пути — идёт в URL. Остальные — простые типы, их нет в пути — query. У `description` здесь нет значения по умолчанию, значит, параметр обязателен: если не передать его, будет 422.
>
> </details>

### CORS: кого касается и когда срабатывает

- CORS проверяет **только браузер**. Nuxt-сервер, `curl`, Swagger и Python-скрипты его не замечают.
- Origin — это `схема://хост:порт`. `http://localhost:3000` ≠ `http://127.0.0.1:3000` ≠ `http://localhost:3001`. В `allow_origins` должен быть ровно тот адрес, который ты видишь в адресной строке браузера.
- Браузер не всегда **блокирует отправку** запроса — иногда он только **не даёт странице прочитать ответ**. Для простых запросов (GET, POST без JSON-тела) запрос уходит на сервер и выполняется. Для остальных (DELETE, PUT, POST с JSON) браузер сначала шлёт «предварительный» запрос `OPTIONS` (preflight) и, если сервер не разрешил, основной запрос не отправляет вовсе.

> **Эксперимент.** Закомментируй в `main.py` блок `app.add_middleware(...)` и сохрани. Затем по очереди: обнови страницу, создай пользователя через форму, нажми «Удалить» у любого пользователя. **Предскажи для каждого действия:** что будет на странице, что в консоли браузера и что в логе Uvicorn?
>
> <details><summary>Ответ</summary>
>
> 1. **Обновление страницы:** список показывается нормально! Его загрузил Nuxt-сервер (SSR), а на сервер CORS не действует.
> 2. **Создание:** на странице «Не удалось создать пользователя». В консоли: `Access to fetch at 'http://127.0.0.1:8000/create_user?...' from origin 'http://localhost:3000' has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present`. Но в логе Uvicorn — `POST /create_user ... 200 OK`: пользователь **создан**, браузер просто не отдал странице ответ. Нажми F5 — новый пользователь в списке.
> 3. **Удаление:** в консоли `Response to preflight request doesn't pass access control check`, в логе Uvicorn — `OPTIONS /users/delete/0 ... 405 Method Not Allowed` и **никакого** `DELETE`. Пользователь не удалён.
>
> Вывод: «список грузится, а кнопки не работают» — классический признак CORS. Верни middleware.
>
> </details>

### Ключ в `v-for` и реактивные данные

- `:key` должен быть **уникальным и стабильным**: `user.id` — да; индекс в массиве — плохо (после удаления индексы сдвигаются, и Vue может перепутать строки с полями ввода); `user.name` — плохо (имена повторяются).
- Не меняй `data` из `useFetch` руками ради «быстрого обновления» (`users.value.push(...)`), пока не уверен, что сервер ответил успехом. Самый надёжный способ показать правду — спросить сервер заново: `refresh()`.

## 8. Диагностика: сначала найди этап

Любую проблему сначала относи к этапу: **запуск → сеть → запрос → ответ → отображение**. Главный инструмент — вкладка Network: она сразу говорит, дошёл ли запрос и что ответил сервер.

| Симптом | Этап | Что проверить |
|---|---|---|
| Любая страница: 500 `Either manifest or precomputed data must be provided` | запуск | Баг Nuxt 4.6.0 на Windows: добавь в `nuxt.config.ts` блок `nitro` из шага 3 и перезапусти `npm run dev` |
| `npm run dev` пишет `nuxt: not found` | запуск | Ты в папке `frontend/`? Был ли `npm install`? |
| Страница Nuxt не открывается вообще | запуск | Запущен ли `npm run dev`, какой адрес он напечатал |
| `npm run dev` пишет `Using alternative port 3001` | запуск | Порт 3000 занят другим процессом (часто — забытым вторым `npm run dev`). Останови его: на 3001 сломается CORS |
| `Ошибка загрузки: [GET] "http://127.0.0.1:8000/users": <no response> fetch failed` | сеть | Запущен ли бэкенд; совпадают ли адрес и порт в `apiBase` с адресом Uvicorn |
| Список есть, кнопки не работают; в консоли `blocked by CORS policy` | сеть | `CORSMiddleware` в `main.py`; совпадает ли `allow_origins` с адресом в адресной строке браузера |
| В Network статус **404** | запрос | Опечатка в пути или в методе; сравни со Swagger. Или объект действительно не найден (`HTTPException`) |
| В Network статус **405** Method Not Allowed | запрос | Путь верный, метод нет: например, `GET` вместо `DELETE` |
| В Network статус **422** | запрос | Response → `detail`: какой параметр и где (`query`, `body`) не подошёл. Частое: query вместо body, строка вместо числа, забыт обязательный параметр |
| В Network статус **500** | ответ | Traceback в логе Uvicorn — это ошибка Python, фронтенд ни при чём |
| Запрос 200, но на странице ничего не изменилось | отображение | Есть ли `refresh()`; обычная переменная вместо `ref`; правильное ли поле выводится (сравни с Response) |
| Пусто на месте значения | отображение | Имя поля в шаблоне совпадает с JSON? `user.Name` ≠ `user.name`. Нет ли `.value` в шаблоне |
| `Hydration ... mismatch` в консоли | SSR | Сервер и браузер нарисовали разное: обычно из-за `Math.random()`, `Date.now()`, `window` в `<script setup>` |
| Правки в `.vue` не видны | запуск | Сохранён ли файл; не упал ли `npm run dev` с ошибкой в терминале |

Порядок действий, когда «ничего не работает»:

1. Работает ли запрос **в Swagger**? Нет → проблема в бэкенде, фронтенд пока не трогай.
2. Есть ли запрос **во вкладке Network**? Нет → код не вызвался (обработчик не привязан, ошибка в Console) или это SSR-запрос — смотри лог Uvicorn и терминал Nuxt.
3. Совпадают ли **метод, URL и параметры** с тем, что делает Swagger? Сравни поле Curl в Swagger и Headers/Payload в Network.
4. Что пришло **в Response**? Совпадают ли имена полей с теми, что ты выводишь в шаблоне?

### Уровень 3. Редактирование

Добавь к каждому пользователю кнопку «Изменить». По нажатию форма заполняется его данными, а кнопка «Создать» превращается в «Сохранить», которая вызывает `PUT /users/update/{user_id}`. После сохранения форма очищается, список обновляется. Ответь на семь вопросов до того, как писать код.

<details><summary>Подсказка</summary>

Нужна ещё одна реактивная переменная — id редактируемого пользователя или `null`, если ничего не редактируем. От неё зависят текст кнопки и то, какую функцию вызывает форма. `UserItem` получает второе событие — `edit`.

</details>

<details><summary>Ответ</summary>

В `UserItem.vue`:

```ts
const emit = defineEmits<{
  delete: [id: number]
  edit: [user: User]
}>()
```

```vue
    <button @click="emit('edit', user)">Изменить</button>
```

В `pages/index.vue`, в скрипт:

```ts
const editingId = ref<number | null>(null)

function startEdit(user: User) {
  editingId.value = user.id
  name.value = user.name
  age.value = user.age
  description.value = user.description ?? ''
}

async function updateUser() {
  await $fetch(`/users/update/${editingId.value}`, {
    baseURL: apiBase,
    method: 'PUT',
    query: { name: name.value, age: age.value, description: description.value },
  })
  editingId.value = null
  name.value = ''
  description.value = ''
  await refresh()
}

function save() {
  return editingId.value === null ? createUser() : updateUser()
}
```

В шаблон:

```vue
    <form @submit.prevent="save">
      ...
      <button type="submit">{{ editingId === null ? 'Создать' : 'Сохранить' }}</button>
    </form>
    ...
      <UserItem v-for="user in users" :key="user.id" :user="user" @delete="deleteUser" @edit="startEdit" />
```

`description` здесь передаётся всегда, даже пустой строкой: в `update_user` у него нет значения по умолчанию, без него будет 422. `user.description ?? ''` — поле формы хранит строку, а у пользователя описание может быть `null`; `??` подставляет пустую строку вместо `null`.

</details>

По очереди внеси одну поломку, **предскажи симптом** (что на странице, в Network, в Console, в логе Uvicorn), проверь, верни рабочий вариант:

</details>

### Уровень 6. JSON-тело вместо query string

В настоящих API данные для создания передают в **теле** запроса в формате JSON, а не в URL. Переделай `POST /create_user`: пусть он принимает JSON `{"name": ..., "age": ..., "description": ...}` и возвращает созданного пользователя объектом, а не строкой. Затем исправь фронтенд. Что увидишь в Network до исправления фронтенда?

<details><summary>Ответ</summary>

Бэкенд — новая модель для входных данных (без `id`: его назначает сервер) и параметр-модель:

```python
class UserCreate(BaseModel):
    name: str
    age: int
    description: str | None = None
```

```python
@app.post("/create_user")
def create_user(data: UserCreate) -> User:
    global global_id
    next_id = global_id
    global_id += 1

    new_user = User(id=next_id, name=data.name, age=data.age, description=data.description)
    fake_user_database.append(new_user)
    return new_user
```

До исправления фронтенда: **422**, в Response `detail` с `loc: ["body"]` и сообщением, что тело отсутствует, — фронтенд по-прежнему шлёт параметры в query.

Фронтенд — `query` меняется на `body`:

```ts
    await $fetch('/create_user', {
      baseURL: apiBase,
      method: 'POST',
      body: {
        name: name.value,
        age: age.value,
        description: description.value || null,
      },
    })
```

`$fetch` сам превратит объект в JSON и поставит заголовок `Content-Type: application/json`. Посмотри в Network → Payload: теперь там Request Payload вместо Query String Parameters. Заметь и новый запрос `OPTIONS` перед `POST`: с JSON-телом запрос перестал быть «простым», и браузер делает preflight (раздел 7).

</details>

### Уровень 7. Перенос навыка: новая сущность от бэкенда до страницы

Сделай список задач (todo) — **полностью сам**, обе половины:

- Бэкенд: модель `Task` (`id`, `title`, `done`), эндпоинты `GET /tasks`, `POST /tasks` (JSON-тело с `title`), `DELETE /tasks/{task_id}`. Хранение — в списке в памяти, как у пользователей.
- Фронтенд: страница `/tasks` со списком, формой добавления и кнопкой удаления; на главной — ссылка на неё.

Порядок: сначала бэкенд, проверка в Swagger, потом ответы на семь вопросов, потом страница. Если ты сделал это без подглядывания — ты применяешь алгоритм, а не шаблон пользователей.

<details><summary>Ответ</summary>

Бэкенд, в `main.py`:

```python
class TaskCreate(BaseModel):
    title: str


class Task(BaseModel):
    id: int
    title: str
    done: bool = False


tasks: list[Task] = []
next_task_id = 0


@app.get("/tasks")
def list_tasks() -> list[Task]:
    return tasks


@app.post("/tasks")
def create_task(data: TaskCreate) -> Task:
    global next_task_id
    task = Task(id=next_task_id, title=data.title)
    next_task_id += 1
    tasks.append(task)
    return task


@app.delete("/tasks/{task_id}")
def delete_task(task_id: int) -> Task:
    for idx, task in enumerate(tasks):
        if task.id == task_id:
            return tasks.pop(idx)
    raise HTTPException(status_code=404, detail="Task not found")
```

### Уровень 8. Всё в Docker

Используя [урок по Docker](docker-for-beginners.md), запусти оба приложения через один `compose.yaml`: сервис `api` (FastAPI) и сервис `web` (Nuxt в production-режиме). Страница должна открываться на `http://localhost:3000`, API — на `http://127.0.0.1:8000`.

Перед тем как писать, ответь: какой адрес API нужен **Nuxt-серверу** внутри Docker-сети, а какой — **браузеру** на твоём компьютере? Совпадают ли они?

<details><summary>Подсказка</summary>

Вспомни раздел 9 урока по Docker («Когда появится второй сервис»): внутри Compose сервисы видят друг друга по имени (`api:8000`), а `localhost` внутри контейнера — это сам контейнер. Браузер же работает на твоём компьютере и про имя `api` ничего не знает. Значит, нужно две настройки: одна только для сервера, вторая — `public`.

</details>

<details><summary>Ответ</summary>

`frontend/nuxt.config.ts` — отдельный адрес для сервера (не `public`: в браузер он не попадёт):

```ts
  runtimeConfig: {
    apiBaseServer: 'http://127.0.0.1:8000',
    public: {
      apiBase: 'http://127.0.0.1:8000',
    },
  },
```

В страницах выбирай адрес по тому, где выполняется код, и дай `useFetch` постоянный ключ:

```ts
const config = useRuntimeConfig()
const apiBase = import.meta.server ? config.apiBaseServer : config.public.apiBase

const { data: users, pending, error, refresh } = await useFetch<User[]>('/users', {
  key: 'users',
  baseURL: apiBase,
})
```

`import.meta.server` — `true` при выполнении на Nuxt-сервере. `key` обязателен: без него Nuxt строит ключ запроса в том числе из `baseURL`, и раз адреса на сервере и в браузере разные, браузер не узнает данные, полученные сервером. Он запросит список повторно, а в консоли появится `Hydration completed but contains mismatches`.

`frontend/Dockerfile`:

```dockerfile
FROM node:22-slim
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
RUN npm run build
EXPOSE 3000
CMD ["node", ".output/server/index.mjs"]
```

`frontend/.dockerignore`:

```text
node_modules
.nuxt
.output
```

`compose.yaml` в корне:

```yaml
services:
  api:
    build: .
    ports:
      - "127.0.0.1:8000:8000"

  web:
    build: ./frontend
    ports:
      - "127.0.0.1:3000:3000"
    environment:
      NUXT_API_BASE_SERVER: "http://api:8000"
      NUXT_PUBLIC_API_BASE: "http://127.0.0.1:8000"
    depends_on:
      - api
```

- `npm ci` — установка строго по `package-lock.json` (аналог `pip install -r` с точными версиями). Если он ругается, что `package.json` и `package-lock.json` не совпадают, выполни локально в `frontend/` команду `npm install` и закоммить обновлённый `package-lock.json`.
- `npm run build` создаёт папку `.output` — готовый сервер. Запускается он обычным `node`, без `npm`. Production-сервер Nuxt сам слушает `0.0.0.0` и порт 3000 (меняются переменными `HOST` и `PORT`).
- `NUXT_API_BASE_SERVER` заменяет `runtimeConfig.apiBaseServer`, `NUXT_PUBLIC_API_BASE` — `runtimeConfig.public.apiBase`. Правило имени: `NUXT_` + путь в `runtimeConfig` заглавными буквами через `_`.
- В браузерном адресе не может быть `api`: это имя существует только внутри сети Compose. Браузер ходит на опубликованный порт твоего компьютера.
- CORS не меняется: страница по-прежнему открыта на `http://localhost:3000`.

</details>

- [ ] Связываю поля формы через `v-model`, а числовые — через `v-model.number`.

### Что дальше

Для рабочего приложения следующие шаги: общий клиент API вместо повторения `baseURL` в каждом запросе (`$fetch.create` в плагине или свой composable в `app/composables/`), отдельные схемы Pydantic для входа и выхода у всех эндпоинтов, база данных вместо списка в памяти, валидация формы до отправки, авторизация (cookie или токен), layouts (`app/layouts/`) для общего меню, Pinia для состояния, общего для многих страниц. <details><summary>Скелет страницы со списком и формой</summary>

```vue
<script setup lang="ts">
type <Сущность> = { id: number, <поле>: <тип> }

const config = useRuntimeConfig()
const apiBase = config.public.apiBase

const { data: <items>, pending, error, refresh } = await useFetch<<Сущность>[]>('<путь списка>', {
  baseURL: apiBase,
})

const <поле> = ref(<начальное значение>)

async function <создать>() {
  await $fetch('<путь>', {
    baseURL: apiBase,
    method: '<МЕТОД>',
    query: { <параметр>: <поле>.value },   // или body: {...}
  })
  await refresh()
}
</script>

<template>
  <form @submit.prevent="<создать>">
    <input v-model="<поле>">
    <button type="submit">...</button>
  </form>

  <p v-if="pending">Загрузка…</p>
  <p v-else-if="error">{{ error.message }}</p>
  <ul v-else>
    <li v-for="item in <items>" :key="item.id">{{ item.<поле> }}</li>
  </ul>
</template>
```

</details>

<details><summary>Скелет компонента</summary>

```vue
<script setup lang="ts">
defineProps<{ <свойство>: <тип> }>()
const emit = defineEmits<{ <событие>: [<аргумент>: <тип>] }>()
</script>

<template>
  <button @click="emit('<событие>', <значение>)">...</button>
</template>
```

На странице: `<Компонент :<свойство>="..." @<событие>="<функция>" />`.

</details>

<details><summary>CORS в FastAPI</summary>

from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:3000"],
    allow_methods=["*"],
    allow_headers=["*"],

</details>

<details><summary>Синтаксис шаблона Vue одной таблицей</summary>

| Запись | Смысл |
|---|---|
| `{{ выражение }}` | Вывести значение текстом |
| `:атрибут="выражение"` | Значение атрибута — выражение, а не строка |
| `@событие="функция"` | Подписаться на событие |
| `@submit.prevent` | И отменить стандартное поведение |
| `v-model="переменная"` | Двусторонняя связь с полем ввода |
| `v-model.number` | Плюс превращение в число |
| `v-if` / `v-else-if` / `v-else` | Показать по условию |
| `v-for="x in список" :key="x.id"` | Повторить для каждого элемента |
